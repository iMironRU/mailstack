# mailstack

Развёртывание и обслуживание почтового стека на одном VPS:

- **[Poste.io](https://poste.io/)** — Postfix + Dovecot + Rspamd + Roundcube (ClamAV отключён ради экономии RAM)
- **Nginx Proxy Manager** — reverse-proxy, держит 80/443, выпускает сертификаты Let's Encrypt
- **Portainer CE** — управление Docker через веб
- **Uptime Kuma** — мониторинг доступности
- **go-autoconfig** — автонастройка почтовых клиентов (Thunderbird / Outlook / Apple Mail)

Резервное копирование — restic в S3, с веб-интерфейсом Backrest поверх.

## Быстрый старт

Проверить, годится ли машина под стек, — ничего не устанавливая и не меняя:

```bash
curl -fsSL https://raw.githubusercontent.com/iMironRU/mailstack/main/mailstack.sh | bash -s -- preflight
```

Проверить уже развёрнутый стенд снаружи, со своей рабочей машины:

```bash
./mailstack.sh doctor --external --host mail.example.com --domain example.com
```

## Что проверяет `preflight`

Скрипт отказывается устанавливать стек, если машина не годится, — вместо того чтобы упасть на середине установки.

**Блокирует:** не root; неподдерживаемый дистрибутив или архитектура; OpenVZ/LXC вместо полноценной виртуализации; нехватка RAM или места на диске; незавершённый `dpkg`; **занятые порты стека**; **конфликтующие пакеты на хосте** (postfix, exim4, dovecot, apache2, nginx — самая частая причина, по которой Poste.io не стартует); недоступность репозиториев Docker.

**Предупреждает:** отсутствие swap; заблокированный провайдером исходящий порт 25; отсутствующий или несовпадающий PTR; hostname не в виде FQDN; рассинхронизация времени по NTP; наличие IPv6 без AAAA/PTR; присутствие IP в блоклистах.

## Проверка репутации IP

`preflight` и `doctor` проверяют внешний IP по 10 зонам: Spamhaus ZEN, SpamCop, PSBL, Barracuda, Mailspike, s5h, CBL, UCEPROTECT 1/2/3.

Две детали, которые часто реализуют неправильно:

- **Spamhaus отказывает публичным резолверам.** Запрос через 8.8.8.8 или 1.1.1.1 возвращает `127.255.255.252` — это отказ в обслуживании, а не листинг. Наивная проверка засчитает его как «IP в чёрном списке». Скрипт различает эти случаи и сообщает о них по-разному.
- **`dnsbl.sorbs.net` исключён намеренно** — сервис отключён в 2024 году, зона всегда отвечает «чисто» и создаёт ложное ощущение покрытия.

## Проверка снаружи

Часть проблем принципиально не видна с самого сервера: локальный `ss` покажет `LISTEN`, даже если провайдер режет порт на своём фильтре. Поэтому `doctor --external` запускается **с рабочей машины**, а не с сервера, и проверяет:

- реальную доступность 25, 80, 443, 465, 587, 993, 995 из интернета;
- что порты админок (81, 9000, 9443, 3001) **не** открыты наружу;
- SMTP-баннеры и совпадение HELO-имени с PTR;
- срок и валидность TLS-сертификата;
- A / MX / SPF / DKIM / DMARC домена.

Совместим с bash 3.2, то есть работает на macOS из коробки.

## Требования

Сервер: Ubuntu 22.04/24.04 или Debian 12/13, x86_64 или arm64, от 2 GB RAM (RAM + swap), от 10 GB свободного диска, полноценная виртуализация (KVM).

Рабочая машина для `--external`: bash, python3, dig.
